# Workflow: mono-instrument

A registered theme for [`landing-page`](../SKILL.md): monochrome, monospace-as-structure, one operable
proof object; motion answers input or a state change, and a self-starting demo is optional and bounded
(`composition-system.md` §4). Its rules come from a reaction ledger — measured public reactions — so
the theme can be re-derived when audiences change.

**Dependency:** the sibling skill directory `mono-instrument/`, installed alongside `landing-page/`. If it
is absent, stop and say so; this workflow has no embedded copy of the rules.

## Required reading

1. [`../../mono-instrument/references/reaction-ledger.md`](../../mono-instrument/references/reaction-ledger.md)
   — the evidence rows, their populations, the method and the tensions.
2. [`../../mono-instrument/references/composition-system.md`](../../mono-instrument/references/composition-system.md)
   — the MUST/SHOULD/NEVER rules, each citing ledger rows, and the checklist.

Then follow [`../../mono-instrument/SKILL.md`](../../mono-instrument/SKILL.md) for the step-by-step
workflow, the per-lane gates and the output contract.

## Order of operations

1. **Target contract + lane** — [`../SKILL.md`](../SKILL.md) §1–§2.
2. **Ledger freshness** — older than six months, or a non-developer audience: re-run the fan-out first.
3. **Fact ledger** — every product claim sourced; no invented metrics.
4. **Page brief** — decision → ledger-row table, tokens with computed contrast, motion inventory, budgets.
5. **Implementation** — Lane A in the app's own stack; Lane B as one self-contained file.
6. **Gates** — the lane's gates plus before/after Lighthouse with the same version.
7. **Browser QA** — desktop and mobile, light and dark, reduced motion, JavaScript off, time-axis motion evidence.
8. **Fix loop** — any failure returns to step 5.

## Output

The page brief with its decision → row table, the receipts listed in `mono-instrument/SKILL.md`
§Output contract, and the delivery URL actually loaded.
