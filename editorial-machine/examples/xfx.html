Authority / choose before running

Permission is not a sandbox.

There is no OS sandbox in any mode — status reports sandbox=none because that is true. A command xfx agrees to run runs with your privileges, your environment, and your network. The three modes below decide only what xfx agrees to start.

ask / safest

Requires a real terminal approval for every change and command. In a pipe or CI, it refuses instead of pretending to ask.

auto / default

Admits reads, bounded reversible workspace writes, and a narrow reporting-only command grammar after structural validation.

yolo / unchecked

Runs no permission check at all and prints a warning to stderr every time. Use it in a container you are willing to lose.

Record / after the turn

Resume the work. Inspect the grant.

Every saved turn goes to an append-only session with an atomically published manifest. Standing approvals are scoped by tool, absolute target, and session. Use --no-save when the turn must leave nothing behind.

Plain truth: file contents and command output returned to the model are also stored verbatim in the owner-only plaintext event log.

~/.xfx/sessions/<id>/
├── manifest.json  # atomically published
└── events.jsonl   # append-only, mode 0600

$ xfx sessions
$ xfx session <id>
$ xfx ask --resume last "continue"
$ xfx status --json
$ xfx doctor --json
Transport / profile-owned

Two backends. One stays on loopback.

Vercel AI Gateway

Authenticated by a nonblank OIDC token or AI Gateway API key from the environment.

Local

llmux

xfx setup llmux probes a local daemon, records the backend and model, and sends no completion request. Keyless mode is enforced to explicit loopback URLs; remote hosts are refused.

Boundary / read before auto or yolo

What xfx refuses is part of xfx.

No quiet stubsAbsent features produce an error, never a quiet no-op. Precedence is fixed: where the README disagrees with docs/parity.md the ledger is right, and where the ledger disagrees with the code the code is right — both documents are then bugs.

No hidden sandboxIn every mode, commands run with your privileges, environment, and network. Permission controls admission, not the behavior of a process after it starts.

No repository takeoverFile tools structurally refuse .git and .xfx in every mode, including yolo.

No upstream identity collisionThe binary is xfx, profile home ~/.xfx, and project file .xfx.json.
