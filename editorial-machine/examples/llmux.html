Why the harness matters

When you chose Claude Code, you also chose your conventions: slash commands, MCP servers, subagents, hooks, and CLAUDE.md rules. Changing model providers should not require rewiring your entire agent stack.

llmux proxies the Anthropic API locally. Every request routes through your daemon, which reads your model name, decides which account and backend serves it, and forwards it there. The result comes back Anthropic-shaped — unchanged to your harness.

  • One Rust binary: daemon, live TUI dashboard, login/import, updater, launcher
  • Multi-account quota-aware scheduling, 429 cooldown parking, Fable weekly ceilings
  • Stable Homebrew channel; a rolling preview channel alongside it
  • Native macOS Islands companion; the KDE/Qt port is a source build

Request receipts and debugging

Routing is not magic. The activity feed prints one row per completed request, and any row opens into a raw viewer that shows all four legs of the wire.

Bodies, headers, SSE events, and rate-limit state are readable as bytes. Copy as curl reconstructs one side of the exchange for replay, with credential values redacted.

Remote-first topology and Islands

The intended shape is one central daemon, with every other machine running the CLI as a pure client: it never starts a local daemon, it points claude at the remote proxy and presents that machine's own issued key.

Each client is pointed at the daemon explicitly — --remote host[:port] for a single invocation, or remote.host in ~/.config/llmux.json. There is no network discovery, and account mutation stays on the daemon's host: in remote mode login and import are refused by name.

  • Per-machine multi-tenant client keys, metered and revocable one machine at a time
  • Provider credentials stay inside the daemon; a client holds only its own issued key
  • Native macOS Islands companion, a KDE/Qt source build, and the terminal dashboard
  • One routing decision point for every machine you work from

Install, operate, and first steps

Get the stable binary from Homebrew:

$ brew install 2lab-ai/tap/llmux

Start the daemon and launch Claude Code in one command:

$ llmux run

Add accounts by browser login, or import supported local credential stores:

$ llmux login
$ llmux import

Prefer the foreground TUI dashboard instead of the background daemon:

$ llmux server

The rolling preview channel and the optional macOS companion are their own formulae. The KDE port is a source build, not a formula:

$ brew install 2lab-ai/tap/llmux-preview
$ brew install 2lab-ai/tap/llmux-islands

Candor

Ownership: llmux is for one human using their own accounts — no credential pooling, no resale.

Policy: routing third-party flat-rate subscription tokens through Claude Code depends on that vendor's current policy and can change without notice. Use it opt-in, with your own accounts, and keep an API-key fallback configured. Anthropic quota headers and vendor subscription-token behaviour may change.

Affiliation: llmux is not affiliated with Anthropic, OpenAI, xAI, or OpenRouter.
